本页保留初版与优化前后的 A/B。三档的吞吐、总内存和安装体积见[优化版横评](WSL-OPTIMIZED.zh-CN.md)。

2026-11-19。在 WSL 2 的 Debian 12 中，将ngx-ipblock-fastlite v1.4.0 与五种实现比较。HTTP 层按精确 IPv4 拦截，防火墙按 TCP 包源地址匹配。为比较直接连接时的开销，本次关闭了 CIDR、Cloudflare 头校验和访问日志。

## 数据

从同一上游提交取 30、180、365 天文件，核验 Git blob 哈希，解析并去重后分别有 153,496、436,778、754,110 个 IPv4。对四字节网络序地址取 SHA-256，按摘要升序依次选出 150,000、400,000、600,000 个，再按地址数值排序。每档的所有实现使用完全相同的成员。三个时间窗口的地址分布也有差异。[上游提交](https://github.com/borestad/blocklist-abuseipdb/tree/eb4a4a4ec7b2453b176cec0e7da0e0fb3033121c) · [输入与抽样摘要](../benchmark/results/wsl-sources.jsonl)

## 实测

本页为历史纯放行数据，不用其 ipset 吞吐评价丢包能力。另见[纯放行开关对照原始记录](../benchmark/results/wsl-ipset-paired.jsonl)及[当前 10% 名单命中横评](../README.md#性能横评)。nftables 缺少可归因的总内存，已从表中移除，原始样本保留。

原生 OpenResty 对照行使用同一 OpenResty 和后端。防火墙行也直接转发 HTTP，同时由内核检查入站包的源地址。本项目行额外执行 HTTP access 钩子，按站点配置解析访客地址并查表。表中吞吐覆盖整条请求路径，未单独计时匹配算法。

HTTP 命中组统一返回 403，以便核对每个请求的结果。本模块默认使用 444，断连会改变连接复用成本。防火墙命中组验证 TCP 超时和 DROP 计数，表中未列 HTTP 拒绝吞吐。包计数与 HTTP 请求数单位不同。

60 万档的放行请求固定来自 127.0.0.1。名单中 127.0.0.0/16 桶为空，查到桶边界就结束。直接转发与启用本模块时，每请求前端 CPU 时间的中位数分别为 6.30 和 6.70 微秒。约 0.40 微秒的差值涵盖整条请求路径，包括进入 Lua 访问阶段、读取域名和客户端地址、解析 IPv4、检查白名单和定位索引桶。各步骤未单独计时。防火墙组在内核按包匹配集合，放行后由 OpenResty 直接转发。进程 CPU 数据无法单独量出内核集合的匹配成本。

内存按存放位置分列。本项目的名单和索引已计入前端进程 PSS。两种防火墙的名单存于 Linux 内核，ipset 的集合大小取自 `ipset list -terse` 的 `Size in memory`，nftables 原生集合本次未测字节数。「—」表示该方案未使用独立的内核名单集合。60 万条时，iptables + ipset 两项实测合计约 22.73 MiB；nftables 缺少内核项，无法比较总内存。

## 优化前后对照

本轮单独比较原版和按桶保存低 16 位、加载时分步 GC 的版本。每档做四对交错 A/B，每次重新启动单 worker 前端。放行和命中各轮换 2,048 个 IPv4，放行地址取自有记录的桶。仅信任回环压测客户端的 Real IP 头。放行使用 wrk 测量转发至同一 204 后端的请求数；命中使用项目自带压测客户端统计默认 444 无响应断连数。每种负载预热 1 秒、测量 3 秒，并发 32。下表为四次采样的中位数，按原版 → 优化版排列。

| IP 条数 | 热态前端总 PSS（MiB） | 放行请求/秒 | 444 断连/秒 |
|---:|---:|---:|---:|
| 150,000 | 13.19 → 12.12 | 136,222 → 137,172 | 54,504 → 54,586 |
| 400,000 | 15.19 → 13.41 | 137,900 → 138,924 | 54,742 → 54,208 |
| 600,000 | 17.39 → 14.19 | 134,743 → 136,187 | 54,829 → 54,834 |

12 对样本中，优化版的前端总 PSS 均较低。该总量包含 master、worker、名单和索引。放行吞吐中位数提高约 0.7% 至 1.1%。40 万条时，四对样本的 444 断连速率均下降，中位数低约 1.0%。这轮使用轮换地址和默认断连策略，性能变化按同轮 A/B 计算。[逐轮数据](../benchmark/results/wsl-suffix-ab.jsonl)

## 复现与适用范围

WSL 内核 6.18.33.2，Intel Core Ultra 5 225，10 个逻辑 CPU。OpenResty 1.31.8.1 来自 APISIX 3.20.0 软件包，匹配库为 0.6.1。iptables 1.8.9、ipset 7.17、nftables 1.0.6、wrk 4.1.0。独立网络命名空间内，单 worker 前端绑定 CPU 0，返回 204 的共同后端绑定 CPU 2，wrk 两线程绑定 CPU 3、4，并发 32，使用长连接。每个方案先预热 3 秒，再连续采样。APISIX 使用独立文件模式和相同上游，对照路由关闭了 ip-restriction。

每档用一个固定的未命中源地址测放行，用一个固定的命中源地址测 HTTP 拒绝，并用首尾两个名单成员做功能验证。结果反映热地址负载。不同实现按固定顺序独立启动，较小的吞吐差异应结合原始样本波动解读。前端 PSS 按 master 与子进程求和，排除压测客户端、共同后端及内核集合。原始样本还包含前端进程 CPU 时间。[逐轮结果](../benchmark/results/wsl-samples.jsonl) · [测试脚本](../benchmark/wsl_compare.py)

```sh
rev=eb4a4a4ec7b2453b176cec0e7da0e0fb3033121c
src=$(mktemp -d)
for days in 30 180 365; do
  curl -fL --compressed "https://raw.githubusercontent.com/borestad/blocklist-abuseipdb/$rev/abuseipdb-s100-${days}d.ipv4" -o "$src/${days}d.txt" || exit 1
done
sudo unshare -nm --propagation private python3 benchmark/wsl_compare.py "$src/run" "$src"
```
